feat(config): central operation-class timeout authority — non-punitive runaway-guards (#3734)

Replaces the accidental, punitive 60s MCP default with an operation-class taxonomy
of generous runaway-guards (interactive 60s / single-llm 300s / multi-llm-panel
900s / pipeline 1800s / network-fetch 120s / async-job-body 3600s; unclassified →
single-llm 300s). One authority in config/timeouts.ts: tools declare a class via
TOOL*CLASS; MCP_TIMEOUTS.perTool is a generated byte-compatible view; maxMs raised
to 3600s. Central tuning via NEXUS_TIMEOUT_MULTIPLIER + per-class
NEXUS_TIMEOUT_CLASS*\*\_MS. Fixes the consensus voting-round 60s short and adds an
internal runaway-guard to backgrounded job bodies. A force-classify test fails if
any registered tool lacks a class.
