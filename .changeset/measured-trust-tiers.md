'nexus-agents': minor
---

The MCP server now records the transport it is connected over, so a stdio server measures its caller at trust tier 1 instead of reporting every request's tier as an unmeasured fallback (#6795). A transport the server cannot identify is not recorded, and its requests stay unmeasured. A child server spawned for an expert CLI is marked with `NEXUS_MCP_CHILD=1` in the generated child MCP config. Its stdio caller is a model, not the operator, so it is recorded as unmeasured.

The caller's tier no longer vouches for the task text. `run_dev_pipeline` and `run` take an optional `sourceTrustTier` (`'1'`–`'4'`, same meaning as `memory_write`'s) that declares where the task text came from. Omitted means `'3'` (untrusted). A declaration can lower trust but never raise it. With a measured caller it is capped at the caller tier. With an unmeasured caller it is capped at `'3'`, and the cap is recorded as a clamp. The dev-pipeline consensus→execute policy gate receives the least-trusted of the measured caller tier, the declared tier and every source the run fetched (research is `'3'`). An unmeasured caller still gives the gate no tier, which it treats as `'4'`. With a stdio caller, `sourceTrustTier: '1'` and no fetched research, the gate now allows; any other combination escalates as before.

`memory_write` applies the same rule. With a measured caller, an omitted `sourceTrustTier` means `'3'`, so an undeclared entry written over stdio is stored as tier 3. It is left out of privileged prompt prefixes unless `allowUntrustedMemory` is set. Declare `sourceTrustTier: '1'` for content you wrote yourself; the caller tier still caps it. With an unmeasured caller, an undeclared entry is stored unlabelled as before, and a declared entry is stored at its declared tier capped at `'3'`.

The gate records how its tier was reached: the measured caller tier (or `unmeasured`), the declared tier (or `undeclared`), whether the declaration was clamped, and the source tiers. That record is in `pipelineState.trustProvenance`, in a debug log, on the `policy.evaluated` bus event as `trustProvenance`, and in the metadata of the durable `security.policy_gate` audit records as `trustProvenance`. The V2 instrumentation contracts built by `orchestrate` and `delegate_to_model` now carry the task text's tier (`'3'` for a measured caller, none for an unmeasured one) rather than the caller's.

Library callers of `runDevPipeline` that pass `trustTier: '1'` must now also pass `sourceTrustTier: '1'` to reach the gate at tier 1. The unused internal `extractCallerInfo` helper is removed.
