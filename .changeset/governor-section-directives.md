The governor section of `CODEOWNERS` is now bounded by two dedicated directive lines, `# @governor-section-start` and `# @governor-section-end`, instead of by a prefix of the human heading (`# Governor's own core — …`) and the `# END governor-owned paths` sentinel. The heading is now free prose: rewording or deleting it no longer changes which paths the governor gates protect. `scripts/governor-section.ts` matches the two directives as whole lines and nothing else — there is no fallback to the old heading — and throws a named `GovernorSectionError` when a directive is missing, duplicated, or out of order, or when the bounded section yields no path pattern. Both governor gates (`check-governor-review.ts`, `check-governor-ratification.ts`) render that refusal as a failing verdict and exit non-zero; before this, a missing end sentinel silently widened the protected set to end-of-file on one side and emptied the ratifier set on the other. The parser's `governorSectionLines` now returns the section's owner-rule lines directly and no longer exposes `started`/`terminated` flags; the `GOVERNOR_SECTION_MARKER`, `GOVERNOR_SECTION_START_PREFIX`, `GOVERNOR_SECTION_END_MARKER` and `GOVERNOR_SECTION_END_LINE` exports are removed in favour of `GOVERNOR_SECTION_START_DIRECTIVE` and `GOVERNOR_SECTION_END_DIRECTIVE`. The set of governed paths is unchanged (14 patterns, pinned by test).
