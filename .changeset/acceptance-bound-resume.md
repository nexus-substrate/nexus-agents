Require verifiable approval evidence for built-in, host-bound development pipelines and resumes. Legacy, invalid, incomplete, or terminal checkpoints block before further work. Start a new run with a new, unused `sessionId` or omit it; reusing an indexed async ID can replay or collide. Custom/unbound compatibility remains unmeasured and cannot reinterpret bound checkpoint data as legacy approval. Adaptive graph `run_pipeline` has no checkpoint qualification consumer.

Preserve captured acceptance input across built-in planning, voting, decomposition, implementation, and QA without changing stage callback arguments. Report host request construction and invocation separately from unmeasured provider delivery. Verified task history still requires fresh implementation and security checks; saved text does not prove filesystem state.

Checkpoints retain the exact bounded informational suffix needed to reconstruct the approved proposal. It may contain sensitive recalled context. Bound files require verified current-user ownership and mode `0600` on supported POSIX systems. Preflight blocks leave existing files unchanged; append failures can leave partial data. Cleanup is attempted after security passes, with no guaranteed retention deadline. See `docs/ops/acceptance-bound-resume-migration.md` for migration and removal steps.

Reject invalid UTF-8, lone UTF-16 surrogates, NUL characters, empty acceptance input, and input above the 256 KiB artifact limit without replacement or silent clipping. Correct or reduce the source explicitly before retrying; combined acceptance-and-plan proposals must also fit the assigned voter budgets.

Failed planner, decomposition, and implementation callbacks now reject with a static error instead of returning fallback or echoed request text, including for unbound library callers. Handle the rejected promise rather than treating failed expert output as a generated artifact.
