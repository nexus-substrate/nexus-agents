`pr_review` now decides what the voter panel reads and what the audit hash binds as two separate questions. Before, one comparison against the 50,000-byte hash cap decided both, so a diff over the cap was packed down to a security-prioritized subset even when every voter could have read it whole. The panel-read budget is now derived from the panel's own seats: the tool resolves the seat-to-adapter assignment once (the same assignment the vote uses, now exported as `assignPanelSeats`), reads each seat's model in the model registry, and hands those seats to the vote as `roleAdapters`, so the budget describes exactly the adapters that review. The budget is the smallest seat window minus a 16,000-token prompt-overhead margin, converted at the shared token estimator's most conservative ratio (3.5 bytes per token); a 200k-token panel reads up to 644,000 bytes. If any seat's model has no registry window (a custom OpenAI-compatible gateway, an OpenCode arm on its own default), has not yet detected its model (the CLI path before first use), the panel cannot be resolved, or the panel is simulated, the budget falls back to the hash cap (the previous behaviour) and the reason names the seat. The hash binding is unchanged: the first 50,000 UTF-8 bytes. The response `coverage` object now carries `panelRead` (`full` | `partial`), `binding` (`full` | `prefix`), `reviewedBytes`, `boundBytes`, `totalBytes` (all UTF-8), `budgetSource` (`registry` | `binding-cap-fallback`) and `budgetDetail`, and is present whenever either the panel read or the binding is not full. The ledger record's summary states both, e.g. `[partial coverage: 2/3 files reviewed, dropped: src/z.ts] [panel read 40,000/61,204 bytes; binding covers first 50,000 bytes; budget: registry (min window 1,000,000 tok (claude-fable-5) − 16,000 × 3.5 B/tok = 3,444,000 B)]`; the stamps are written before the PR title, with the dropped-file list first, so the store's 500-character summary cap truncates the title before either disclosure. A verified approve is still degraded to `abstain` when the panel read is partial; when the panel read everything and only the binding is a prefix, the approve stands and the record discloses the prefix.
