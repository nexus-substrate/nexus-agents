The codex adapter now translates a registry model id to the slug the `codex` binary accepts, as the claude, opencode and gemini adapters already did (#5091). `task.model` carries the canonical registry id (`codex-5.3`, via resolve-model-for-tier → composite-router → orchestrate-command), and both codex transports — `-m` in `codex-adapter.ts` and the MCP `model` argument in `codex-mcp-adapter.ts` — passed it through verbatim, which codex rejects. Both now call `toCodexModelSlug`, which reads the registry's `cliModelName` through the new CLI-scoped `resolveCliModelName(cli, model)` helper in `config/model-config-helpers.ts`; a value that is already a slug passes through unchanged, and a model unknown to the registry is passed through verbatim with a warning (the same fail-open choice the claude and opencode adapters make). Latent until `NEXUS_ROUTE_MODEL_SELECTION=true`, which is default off.

Translation alone would still have failed, because two of the three codex targets were themselves dead. Checked against `~/.codex/models_cache.json` on codex 0.146.0 (`visibility: "list"`: gpt-5.6-sol, gpt-5.6-terra, gpt-5.6-luna, gpt-5.5, gpt-5.4, gpt-5.4-mini, gpt-5.3-codex-spark), `gpt-5.2-codex` and `o3-mini` are not served. Per the 7-voter panel (5-1), `codex-5.2` now points at `gpt-5.3-codex-spark` and `codex-5.1-mini` at `gpt-5.4-mini` (`codex-5.3` → `gpt-5.4` was already served and is unchanged). Each entry's display name, notes, context window, max output and pricing now describe the slug it points at, taken from the models.dev snapshot (2026-08-31): spark 128K / 32K out / $1.75–$14 per 1M; 5.4-mini 400K / 128K out / $0.75–$4.5 per 1M. Quality scores are carried over as the codex arm's tier positions (models.dev does not score quality, and omitting them would drop the entries from routing); only 5.4-mini's `cost` moved (7 → 9) to match the registry's own price scale, and the entry comments say so. `OPENAI_MODELS.GPT_5_2_CODEX` is registry-derived and therefore now reads `gpt-5.3-codex-spark`; its key is a public export and is not renamed here (#5489).

Routing consequence, disclosed rather than tuned: with `NEXUS_ROUTE_MODEL_SELECTION=true`, `resolve-model-for-tier` ranks the balanced codex tier by `codeGeneration`, where `gpt-5.5`, `codex-5.3` and `codex-5.2` tie at 10, and breaks the tie on the higher `cost` score — so `codex-5.2` (cost 7) wins over `codex-5.3` (5). It already did; what changes is that the balanced codex tier now runs the smaller `gpt-5.3-codex-spark` instead of being rejected for naming `gpt-5.2-codex`. The carried-over scores are not a measurement of spark, so a test pins the current resolution to make any rescore a visible decision. `check:pricing-drift` (non-blocking) now reports `codex-5.1-mini contextWindow 400000 → 272000` against litellm: models.dev records the total context window and litellm the max input tokens; the registry follows models.dev, as the other entries do.

`nexus-agents verify` gains a `Codex Models` check that reads the same cache and reports, per codex registry entry, whether its `cliModelName` is served: all served passes and names them; an unserved slug warns and names it; a missing, unparseable or empty cache — or a registry with no codex entries — reports `unmeasured` (rendered as a warn whose message says so), never a pass. A registry test now also asserts every codex `cliModelName` is unique across the whole in-tree registry.
