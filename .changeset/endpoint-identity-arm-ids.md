Routing arm ids can now carry an endpoint identity (#4392 increment 1). `ApiArmId` is `api:<endpoint>` over a validated segment (lowercase alphanumerics plus `.`, `_`, `-`; 1–64 chars; no `:`, `/`, `@` or whitespace, so a base URL or credential can never become an arm id) instead of a closed four-vendor enum; the four existing ids (`api:anthropic`, `api:openai`, `api:google`, `api:custom-openai`) are unchanged and previously persisted outcome records keep parsing. New `isApiArmId()` runtime guard. `routingArmDisplaySlot()` collapses an `api:*` arm it does not recognise to the `opencode` slot explicitly instead of returning the raw id. `CircuitBreakerRegistry`, `CircuitError.cliName`, `CircuitStateChangeEvent.cliName`, `getCliCircuitBreakerSnapshot()`, `getDefaultConfig()` / `createCapacityTracker()` and `RegistrySnapshot.cachedAdapters` are typed over `RoutingArmId` rather than `CliName` (behaviour for CLI names is unchanged; readers that assigned those values to a `CliName`-typed binding need a display-slot collapse). `UnifiedAdapterRegistry` gains `registerApiArm()` / `getAdapterForArm()`; an `api:*` arm is never synthesised, only returned when registered. No routing behaviour changes: `createAllAdapters()` mints exactly the same arm ids as before in both billing modes.
