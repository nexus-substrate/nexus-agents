'nexus-agents': minor

`nexus-agents vote` takes two new flags. `--strategy <simple_majority|supermajority|unanimous|proof_of_learning|higher_order|opinion_wise>` sets the voting bar with the same enum the `consensus_vote` MCP tool accepts and passes it to the engine unchanged; `--threshold majority|supermajority|unanimous` remains as the legacy spelling, and `--strategy` wins when both are given (the engine's existing `resolveStrategy` rule, so the CLI and the tool agree). `--ratifies-pr <number>@<40-hex-lowercase-sha>` binds the vote's audit record to a governor-path PR at the head the panel reviewed: the persisted record carries `ratifiesPr: { pr, headSha }` (schema 1.10) alongside the effective `errorPolicy` (1.11), the command prints `record <id> bound to PR <n> @ <sha>` next to the existing `Audit record #<seq> written (<id>)` line, and `scripts/append-ratification-record.ts --record-id <id>` then copies the record into the committed ledger for the governor gate. Both flags refuse an invalid value with a message naming the expected form instead of silently dropping it: an unknown strategy, a binding without `@`, a short or uppercase sha, a PR number of 0 or a non-integer. A bound vote run below the governor bar (`--strategy supermajority --error-policy absolute_quorum`) is still recorded as run and prints a one-line notice naming the bar; the ledger gate, not the CLI, judges it.
