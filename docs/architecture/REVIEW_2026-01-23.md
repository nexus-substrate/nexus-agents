## Phase 1: Naming Entropy Analysis

### Files with "Enhanced" Suffix

| File                                                        | Canonical                | Status                        |
| ----------------------------------------------------------- | ------------------------ | ----------------------------- |
| `src/cli-adapters/adapters/gemini-adapter-enhanced.ts`      | `gemini-adapter.ts`      | **Active naming entropy**     |
| `src/cli-adapters/adapters/gemini-adapter-enhanced.test.ts` | `gemini-adapter.test.ts` | **Test for enhanced variant** |

### Analysis

**gemini-adapter.ts vs gemini-adapter-enhanced.ts:**

- **Original (`gemini-adapter.ts`):** 125 lines, basic subprocess adapter, uses `GeminiResponseParser`
- **Enhanced (`gemini-adapter-enhanced.ts`):** 451 lines, adds tiered timeouts, circuit breaker, resilient parser, retry logic

**Current Usage:**

- `factory.ts` imports `EnhancedGeminiCliAdapter` (line 14) and creates it for all Gemini requests
- The original `GeminiCliAdapter` is exported but **only used in tests**
- Both are exported from `adapters/index.ts`

**Recommendation:** Merge enhanced features into canonical `gemini-adapter.ts`. The original file is effectively dead code in production.

### Other Naming Patterns Checked

- `*-v2*`: No matches in source code
- `*-new*`: No matches in source code (only in node_modules)
- `*-updated*`: No matches in source code (only in node_modules)
- `*-rewrite*`: No matches in source code (only husky hooks)

### Adapter Duplication

There are **two adapter systems**:

1. **`src/adapters/`** - Direct API adapters (OpenAI SDK, Anthropic SDK, etc.)
2. **`src/cli-adapters/`** - Subprocess adapters wrapping CLI tools (claude, gemini, codex)

Both are valid for different use cases:

- API adapters: Direct integration, streaming, lower latency
- CLI adapters: Tool-based, sandboxed, uses local auth
