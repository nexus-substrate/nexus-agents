PIPELINE NOTE: ci.yml `commitlint`, `changeset-check`, `producer-consumer-check` and `model-string-drift` gain an `Assert checkout completed (#4932)` step directly after `actions/checkout` (#4932, 2026-09-14) — STRUCTURAL for the four #5396 gates; no gate condition, script, or `ci-success.needs` changes. A checkout that hung until `timeout-minutes` cancelled the job (four in one afternoon) was reported as the JOB'S name failing ("Commit Messages: fail", "Producer/Consumer Check: fail") for a check that never ran. The step is `if: always()` so it runs after a cancelled or failed checkout, and its body `test -d .git && git rev-parse --verify HEAD` emits `::error::checkout did not complete …` and exits 1 when the tree is absent (executed: absent → 1, unborn HEAD → 128, present → 0). It is inline rather than in `setup-node` because a `uses: ./.github/actions/...` step is resolved from the checked-out tree and cannot run without it. Option 1 (retry the checkout) was deliberately NOT added: a retry masks the signal this step names.
