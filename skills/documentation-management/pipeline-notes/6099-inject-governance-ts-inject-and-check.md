PIPELINE NOTE: inject-governance.ts `inject` and `check` now share ONE render of CLAUDE.md, `renderClaudeMd` (#6099, 2026-09-13) — SEMANTIC for what a green local `governance:check` promises. After #6084 and #6097 the check regenerated only the GENERATED:FROM_AGENTS block through the shared prettier pass and simulated the rest of `inject` by splicing the on-disk block back into that partial regeneration (`withOnDiskBlock`), so parity with CI's "inject, then `git diff --exit-code CLAUDE.md`" was closer but not total: a stale MODEL_LIST — the one generated section that sits OUTSIDE the agnostic block — passed locally and failed CI, and the "parity not total" residual was stated in the #6087 note rather than closed. The contrarian seat on both #6097 panels argued the structural fix. `renderClaudeMd(currentClaudeMd)` is `applyAllSectionInjections` (the agnostic block from AGENTS.md, then TOOL_INDEX, WORKFLOW_INDEX, MODEL_LIST, the inline counts, VERSION — the order `inject` always applied) followed by `formatWithPrettier`; `inject` writes that string, `check` fails when it is not byte-equal to the file. No generator was duplicated; `withOnDiskBlock`, its `BLOCK_NOT_IN_REGENERATION` guard, `sliceBetween`, `formatForCheck` and both per-cause describers are gone. The block-vs-outside-block distinction is KEPT but DERIVED: `isInsideAgnosticBlock` places the first differing line relative to the on-disk markers (both texts agree before that line, so a marker that precedes it is on the same line in both; a missing END marker reads as inside), and the two remedies still differ — inside, the prose is owned by AGENTS.md and a hand edit is reverted; outside, `inject` alone is the fix. What changed in the report: ONE cause per run, the first difference, where #6087 measured and printed both independently — with a single comparison there is no second measurement to hide, and one `inject` repairs every cause at once, so the (c) test now asserts the first line is named and the round-trip passes. Formatter errors are now a typed `FormatError` thrown by `formatWithPrettier` itself (message `could not format <path>: …`), so `checkClaudeMd` catches exactly that and lets generator invariants (malformed AGNOSTIC:BODY markers) keep throwing as before. Known and deliberately NOT papered over: AGENTS.md's own TOOL_INDEX / WORKFLOW_INDEX copies are hand-held — `inject` never regenerates them there (#6105) — so a perturbation of AGENTS.md's table is neither repaired by `inject` nor, now, reported by `check` (the render copies the stale table and overwrites it in CLAUDE.md); the (f) fixed-point test therefore perturbs CLAUDE.md only, from a pristine AGENTS.md, and cites #6105 rather than asserting a repair `inject` does not make. Six (f) cases (agnostic prose, rules table, skills list, tool index, version stamp, model list) plus (g) inject-twice over every written file; mutation-verified: render skipping a section, check comparing only the block, and dropping the prettier pass each fail a named test. Also folded `checkGovernance`'s inline registry object into the existing `loadAllRegistries()` — it was the same five extractors written twice — and the registries are passed into the render so `check` does not parse the sources a second time.
