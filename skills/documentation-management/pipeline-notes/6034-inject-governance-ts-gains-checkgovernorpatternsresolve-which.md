PIPELINE NOTE: inject-governance.ts gains checkGovernorPatternsResolve, which fails governance:check when a CODEOWNERS governor pattern matches no tracked file (#6034, 2026-09-09) — SEMANTIC for what a green governance:check asserts. `governorPathsFromCodeowners` returns the first token of each governor-section line, so a pattern matching nothing on disk was indistinguishable from one matching everything it should: count unchanged, `started` and `terminated` healthy, #6030's non-empty guard satisfied, and the path silently UNGOVERNED. Fail-open. All 14 current patterns resolve, so it was latent. Three panel conditions shaped the implementation and each is load-bearing. It matches with `matchesCodeownersPattern` against `git ls-files` — the SAME matcher both governor gates use — because a separate glob engine or a bare existsSync could pass a pattern the gates cannot match, which is the same fidelity defect one layer over. It runs under governance:check on EVERY PR rather than gated on CODEOWNERS edits, because the likelier drift is not a typo but a RENAME: a PR moves src/audit/ and never touches CODEOWNERS, so a path-filtered check would not run on the PR that breaks it. And it names the pattern AND its line, because "some pattern is stale" is not actionable on a 14-entry list. Deliberately NOT inside the parser: it is a pure text function with 10 hermetic test sites, and a stale pattern reaching main would make it throw, rendering both governor gates `indeterminate` and blocking every PR in the repo until CODEOWNERS was fixed — a repo-wide outage keyed on one string, where a check fails only the PR that introduces the drift. THE VOTE IS THE PART WORTH RECORDING: the first panel chose the parser option 4-of-6, and two of those four reasoned from a claim in the proposal that was FALSE — that a typo'd pattern also drops that line's owner from the ratifier set. It does not; `governorOwnersFromCodeowners` collects @ tokens from `slice(1)` and never consults the pattern. The Scope Steward seat caught it, the correction was posted to #6034, and the same fork re-voted 6-0 the other way. Verified end to end against the real tree rather than only in unit tests: a typo reports CODEOWNERS:28, a stale glob reports CODEOWNERS:37, a clean tree exits 0. The pure half lives in scripts/governor-section.ts as `unresolvedGovernorPatterns` so the decision is testable without a working tree, which also gives it a real cross-file consumer. The `git ls-files` catch is fail-closed and is the one branch with no test — stated rather than covered by a contrived one. checkGovernance hit its 50-line cap, so the four cross-adapter doc gates are grouped into checkCrossAdapterDocGates, the device checkStrategyRegistryGates already uses in that same function, rather than raising the cap (#6008).
