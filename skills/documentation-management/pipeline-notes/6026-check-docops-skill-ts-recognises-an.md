PIPELINE NOTE: check-docops-skill.ts recognises an INVOCATION of the escape hatch rather than any OCCURRENCE of it (#6026, 2026-09-09) — SEMANTIC for when the gate can be bypassed. Line 264 was `commitMessage.includes('[skip-docops]')` over the whole PR commit range, so a commit that merely NAMED the token disabled the gate and printed "Check bypassed (escape hatch)" with exit 0. Measured on main, not hypothesised: 12 occurrences across 8 commits, 8 of them prose. All 4 commits carrying only prose occurrences changed a declared pipeline file and updated no skill, so all 4 bypassed silently — and every one of those 4 is a change TO THIS GATE (the commit that introduced it, the #2411/#2413 fix, the #5028/#5029 fix for the commit-RANGE half of this same bug, and the dependabot exemption). Because you cannot modify an escape hatch without writing its name, every change to this gate had bypassed this gate: a 100% bypass rate on its own maintenance history, and the reason the bug survived one prior fix aimed squarely at it. #5028 narrowed WHICH commits are searched; it did not change HOW the token is recognised inside them. Caught when PR #6025's commit body said "rather than waved through with [skip-docops]" and the gate obligingly stood down. The recogniser now lives in scripts/docops-escape-hatch.ts: a token that BEGINS a line (optionally indented — squash bodies are) or ENDS one is an invocation; a token with words on both sides is prose. Verified against all 12 historical occurrences, which are committed as a fixture so the classification is an executable assertion rather than a claim in an issue. The 4 genuine invocations keep working — 3 are the trailing `[skip ci]` shape, 1 is standalone — so no documented spelling changed and no contributor relearns anything; the script's header and both help strings now state the positional rule. Ratified 6-1 at supermajority with absolute_quorum, leading option 4 of 6 approvers. Two panel findings shaped the result. The contrarian's objection was UPHELD against this issue's own filed suggestion: a recogniser shared with check-npx-tsx.sh and the #5028 range fix would be an abstraction over a coincidence — same defect family, three different matching domains (a token in a commit message, an invocation in a file, a set of commits in a range) — so no cross-gate helper was extracted. The architect's acceptance test was that the fix PR must not bypass the gate it fixes, since its own commit body necessarily writes the token; that case is a test. Separately, the SEAM was untested and this is the part worth remembering: the recogniser had 25 tests and the gate had 10, and reverting performCheck to bypass on any occurrence kept all 35 GREEN. Both halves were covered; the wire between them was not, and the wire is what decides whether CI passes. performCheck now takes an injectable CheckInputs so the decision is drivable, and the mutation that previously passed 10/10 undetected now fails. A near-miss is also reported instead of swallowed — a mention found with no invocation prints the offending lines and the positional rule, because an author who meant to bypass and wrote it mid-sentence should be told, not silently overruled.
