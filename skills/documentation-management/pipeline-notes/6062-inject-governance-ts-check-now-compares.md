PIPELINE NOTE: inject-governance.ts `check` now compares the GENERATED:FROM_AGENTS block after the SAME prettier pass `inject` writes with (#6062, 2026-09-10). `writeFormatted` ran generated CLAUDE.md through prettier, but `checkClaudeAgnosticBlock` regenerated the block from the RAW AGENTS.md slice and compared bytes, so any prose prettier reshapes — an inline code span split across a line break is the easiest trigger — made `check` fail permanently while prescribing an `inject` that changed nothing. The prettier call is now one exported helper, `formatWithPrettier`, used by both the writer and the check; the check runs its regeneration through it and compares only the marker-bounded block (prettier's view of the rest of the file, e.g. the end-of-file newline, is not agnostic-body drift). `inject` is therefore idempotent with respect to `check`: running inject makes check pass, and formatter-reshaped prose no longer produces a permanent failure. On a genuine mismatch the message prints the first differing CLAUDE.md line number (1-based) with the `expected:` and `on disk:` text, then the existing remedy. Because prettier 3 has no synchronous format, `checkGovernance()` is now ASYNC (supersedes the "checkGovernance() is sync" clause in the #5142 note above); the CLI awaits it. Three tests in scripts/inject-governance.test.ts, two mutation-verified (drop the check-side prettier pass; drop the line number).
