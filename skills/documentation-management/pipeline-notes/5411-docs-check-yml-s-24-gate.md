PIPELINE NOTE: docs-check.yml's 24 gate invocations migrated from npx-based `tsx` invocation to `pnpm exec tsx` (#5411, 2026-09-04) — NON-SEMANTIC: same scripts, same arguments, same verdicts; only how the TypeScript interpreter is resolved changed. The reason it is not a cosmetic swap: `tsx` was declared in NO package.json in the repo and never had been (`git log -S'"tsx"' -- package.json` is empty), while `.github/actions/setup-node` caches `pnpm` — the pnpm STORE, not `~/.npm/_npx`. npx resolves local `node_modules/.bin` -> npx cache -> registry, and on a fresh runner the first two are empty, so every one of these steps fetched tsx plus its esbuild platform binary over the network. Measured rather than inferred: `scripts/arch-lint.ts` is a bounded ~1400-file scan that runs in 3.95s locally against a warm npx cache and took 6m51s as a CI step; the Lint job was killed at its 10-minute cap twice while reporting 0 lint errors, and took 10m22s on the run that passed. The tell was that the same step varied 4m51s / 6m57s / >10m04s across one hour — a step whose real cost is four seconds cannot vary by six minutes for reasons internal to itself. tsx is now pinned at 4.23.13 in root devDependencies, so it arrives in the lockfile and therefore in the store CI already caches; locally the same script drops to 1.85s. This also closes a supply-chain gap orthogonal to speed: a repo that pins every Action to a full commit SHA was executing all of its governance and drift gates under an unversioned interpreter fetched at job time. Ratified by a 7-voter panel, unanimous among approvers (6/6) for declare-and-`pnpm exec`; the dissent held that `pnpm exec` fails from a package subdirectory, which was tested and is false here (it resolves from the repo root, `packages/nexus-agents`, and a nested `src/` dir, because pnpm walks up to the workspace root). All 28 tsx-invoking jobs across all workflows were checked for `setup-node` with install enabled before the sweep; none would break. `governor-review.yml` deliberately keeps the npx-based form — governor-owned path per CODEOWNERS, the same carve-out as #5400 — and the new ratchet in ci.yml's lint job excludes it by name. That ratchet was verified able to FIRE, not assumed: clean on the fixed tree, exit 1 on a reintroduced npx-based invocation, and still clean with governor-review.yml's three occurrences present. NOT swept here and tracked separately: docs prose, JSDoc usage examples, generated files (`concern-registry.json`, `tool-distinctness-baseline.json`, `capabilities.md`, `skills-index.md`) which must change at their generator rather than by hand, a test fixture in check-docops-skill.test.ts that asserts a diff line containing the old form, the frozen CHANGELOG, and 50 npx-based shebangs — `env` takes a single argument, so those cannot take the `pnpm exec` form at all.
