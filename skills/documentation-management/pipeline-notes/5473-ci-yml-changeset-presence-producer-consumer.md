PIPELINE NOTE: ci.yml (Changeset Presence, Producer/Consumer, commitlint) and docs-check.yml (Schema-Fan-Out) diff against `origin/${{ github.base_ref || 'main' }}` instead of `${{ github.event.pull_request.base.sha }}` (#5473, 2026-09-04) — SEMANTIC for the gates' INPUT, not their verdict logic: the scripts are unchanged and their default base is already `origin/main`. Why: `pull_request.base.sha` is recorded in the event payload and does not follow `main` as other PRs merge; on the merge-ref checkout that `pull_request` events use, the three-dot diff from that stale SHA contains every file merged to `main` since the PR's branch point. Observed on PR #5470 (docs-only): Changeset Presence failed twice — original run and a rerun — naming the six `src` files PR #5469 had merged in the window, and the API's `base.sha` only moved to the current tip after a synchronize (rebase) event. The inverse also held: a `src` PR with no changeset would pass if another PR's changeset landed in the window, so the gate could not fail for the reason it exists. `origin/<base>` is fetched at checkout time (all four jobs use `fetch-depth: 0`), so the merge-base is real; the `|| 'main'` fallback keeps the expression valid outside `pull_request` events, though every affected job is already gated on that event. Executed locally on the branch before pasting: the three scripts against `origin/main` were clean and `commitlint --from origin/main --to HEAD` linted exactly the branch's own commit (it caught a disallowed `ci:` type that the husky hook had missed in a worktree without node_modules).
