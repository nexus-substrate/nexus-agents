PIPELINE NOTE: inject-governance.ts is now a PRECONDITION of the governor-path ratification exemption, and the exemption blanks whole generated SPANS rather than the stamp line alone (#6022, 2026-09-09) — SEMANTIC for which doc regenerations demand owner ratification. #5944 exempted a PR whose only governed-file change was the `_Governance Version:_` line. Since #5943 made that stamp content-hashed over GOVERNANCE_STAMP_SOURCES, registering an MCP tool moves BOTH the digest AND the TOOL_INDEX list and count, so the change was two regions, not one, and the exemption never applied: adding a tool required owner ratification because a count it feeds lives in a governed file. Measured — a comment-only edit to expert-config.ts moved the digest 4135f4858df6 -> 9dc1227d0634 and turned a four-line lint cleanup red. The exemption now normalises the CONTENT between the markers of a named subset — VERSION, TOOL_INDEX, WORKFLOW_INDEX — before comparing base to head. That half ALONE is a real bypass: everything between two markers would become free-form text that skips ratification. It is therefore gated on `injectorIsClean()`, a real `inject-governance.ts check` subprocess, so each exempted span is verifiably what the deterministic renderer produces from in-repo sources rather than whatever the PR author typed. `injectorIsClean` is a REQUIRED parameter of `stampOnlyExemptFiles`, not a defaulted one, so a caller that omits it is named by the compiler instead of silently receiving the widened exemption unguarded; it fails closed on a non-zero exit, a spawn error, a timeout or a missing status, because "could not determine" and "clean" must not collapse. RULES_INDEX is deliberately OUT of the subset: its source `.rules/` is itself governor-gated since #5999, so a PR that moves it already needs ratification upstream. MODEL_LIST has the strongest case to join (model additions are the most frequent change here, and #5491 held model data is not governance content) but was not what the panel approved — filed as #6024 for its own vote, because widening a governance exemption past its mandate is the thing these gates exist to prevent. The span names are DERIVED from MARKERS, not hand-copied, so the subset cannot name a span that does not exist. That derivation is why `scripts/governance-markers.ts` now exists: importing the names straight from inject-governance.ts created a CIRCULAR import (inject-governance already imported GOVERNANCE_STAMP_DIGEST_LENGTH from governance-stamp-exemption), and under ESM a cycle leaves one side's bindings in the temporal dead zone during module init — the stamp pattern silently degraded and 29 injector checks stopped being able to fail. A gate that cannot fail, introduced by the change whose whole purpose is stopping gates that cannot fail. MARKERS moved to a leaf module both sides import. Worth knowing for anyone debugging that suite: inject-governance.test.ts MUTATES tracked files and only cleans up when it PASSES — it appends a probe comment to mcp/tools/index.ts to verify the digest moves — so the first genuine failure left the artifact behind and contaminated every later run, and a `git stash` produced a spuriously clean 76/76 baseline. Only cleaning artifacts before EACH run gave a trustworthy bisect. Ratified 6-1 at supermajority with absolute_quorum; the named-subset option took 5 of 6 approvers.
