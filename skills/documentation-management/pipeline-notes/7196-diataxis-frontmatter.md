PIPELINE NOTE: #7196 (epic #7203) adds a `Diátaxis Frontmatter` job (`diataxis-frontmatter`) to `docs-check.yml` and to the `docs-success` needs list. `docs-success` is not yet a required branch-protection context, so the job becomes merge-blocking when #4802 makes Docs Success required; until then a red run is visible but does not stop a merge. It runs `scripts/check-diataxis-frontmatter.ts`, which scans `docs/**/*.md` except the generated `docs/api/` and checks the `diataxis: tutorial | how-to | reference | explanation | none` and `audience: user | project` frontmatter defined in `skills/diataxis/SKILL.md`. An invalid value, a list value, an empty key, malformed frontmatter, or `diataxis: none` on a page outside the kinds in `docs/ops/diataxis-none-kinds.json` fails. Missing declarations are a per-page ratchet: `docs/ops/diataxis-frontmatter-baseline.json` lists, per key, the exact pages allowed to omit it (seeded with all 220 pages for both keys). An undeclared page outside the set fails, as does a stale entry (the page now declares the key, or the path no longer exists). `--update-baseline` only removes entries; adding one needs `--allow-growth`. Zero pages scanned fails as `unmeasured`, and an unreadable baseline or kinds file fails too. The script is also added to the workflow's push `paths`.
