## Why Nexus Agents?

Building reliable multi-agent systems is hard. Models hallucinate, fail silently, and disagree with each other. Nexus Agents solves this with **research-backed protocols** that have been validated in academic literature.

<CardGrid stagger>
  <Card title="5 Specialized Experts" icon="puzzle">
    Code, Architecture, Security, Performance, and Research experts - each with domain-specific prompts and capabilities. The Tech Lead orchestrates them automatically.
  </Card>
  <Card title="Byzantine Fault Tolerance" icon="shield">
    When agents disagree, Aegean consensus and CP-WBFT protocols ensure correct decisions even with faulty or malicious agents. Validated with 85.7% fault tolerance.
  </Card>
  <Card title="Intelligent Routing" icon="rocket">
    LinUCB contextual bandits learn which model works best for each task type. TOPSIS multi-criteria ranking optimizes for quality, cost, and latency simultaneously.
  </Card>
  <Card title="8 Memory Systems" icon="information">
    Graph memory for relationships, session memory for context, typed memory for structure, and more. MIRIX six-type architecture validated at 85.4% benchmark accuracy.
  </Card>
</CardGrid>

## Quick Start

Get up and running in under 5 minutes.

<Tabs>
  <TabItem label="npm">
    ```bash
    # Install globally
    npm install -g nexus-agents

    # Verify installation
    nexus-agents doctor

    # Start the MCP server
    nexus-agents
    ```
  </TabItem>
  <TabItem label="pnpm">
    ```bash
    # Install globally
    pnpm add -g nexus-agents

    # Verify installation
    nexus-agents doctor

    # Start the MCP server
    nexus-agents
    ```
  </TabItem>
  <TabItem label="npx">
    ```bash
    # Run directly without installing
    npx nexus-agents doctor

    # Start the MCP server
    npx nexus-agents
    ```
  </TabItem>
</Tabs>

### Claude Desktop Integration

Add to your Claude Desktop config (`~/.claude/mcp.json`):

```json
{
  "mcpServers": {
    "nexus-agents": {
      "command": "nexus-agents",
      "args": ["--mode=server"]
    }
  }
}
```

Then ask Claude: **"orchestrate: Review this code for security issues"**

## Core Capabilities

<CardGrid>
  <Card title="MCP Protocol" icon="external">
    **Native MCP support** for Claude Desktop and Claude CLI. All tools are discoverable and documented with Zod schemas.

    - `orchestrate` - Coordinate expert execution
    - `create_expert` / `execute_expert` - Dynamic experts
    - `consensus_vote` - Multi-agent voting
    - `memory_query` / `memory_stats` - Memory system
    - Plus 9 more tools (15 total)
  </Card>
  <Card title="CLI Adapters" icon="laptop">
    **Zero-credential OAuth** integration with external CLI tools. No API keys stored - all authentication via OAuth 2.0/PKCE.

    - Claude CLI (Opus 4.6, Sonnet 4.5)
    - Gemini CLI (2.5 Pro, Flash)
    - Codex CLI (GPT-5.x family)
  </Card>
  <Card title="Workflow Engine" icon="document">
    **YAML-based workflows** for repeatable processes. Parallel execution, dependency resolution, and step-level error handling.

    ```yaml
    steps:
      - id: analyze
        agent: code_expert
        parallel: true
    ```
  </Card>
  <Card title="Consensus Protocols" icon="approve-check">
    **11 research-backed protocols** for different scenarios. Simple majority for speed, Aegean for Byzantine tolerance, Reflexion for iterative improvement.

    - Task-aware protocol selection
    - Multi-agent critique loops
    - Anti-conformity scoring
  </Card>
</CardGrid>

## Architecture at a Glance

```
External Interface Layer
├── MCP Gateway (Claude Desktop/CLI)
├── REST API (CI/CD, enterprise)
└── Standalone CLI (direct orchestration)
        │
Internal Orchestration Layer
├── Event Bus (agent-to-agent messaging)
├── Tech Lead Router
├── Expert Pool (Code, Security, Arch, Perf, Research)
└── Consensus Engine
        │
Execution Layer
├── CLI Adapters (subprocess)
├── Model APIs (HTTP)
└── Workflow Engine
```

<Aside type="tip">
  The hybrid architecture means you can use nexus-agents as an MCP server for Claude, a standalone CLI for scripts, or a REST API for CI/CD - all from the same codebase.
</Aside>
